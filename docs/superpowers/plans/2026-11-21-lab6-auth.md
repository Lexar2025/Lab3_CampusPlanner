# ЛР №6: Авторизация и защищённые маршруты — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить в Campus Planner вход через учебный API, хранение токена в `expo-secure-store`, восстановление сессии через `GET /auth/me`, защищённые маршруты `(app)` и выход, не ломая локальные задачи ЛР1–ЛР5.

**Architecture:** Токен и пользователь живут в `AuthContext`; корневой layout ждёт `isLoading` и переключает группы `(app)` / `(auth)` через `Stack.Protected`. `TasksProvider` переезжает внутрь `(app)`, поэтому задачи не переходят между сессиями. Сетевой слой состоит из `http.ts` (включая `authorizedFetch`) и `auth.ts`; `authStorage.ts` — единственное место работы с `SecureStore`.

**Tech Stack:** Expo SDK 57, React Native 0.86.3, React 19.2.3, Expo Router ~57.0.31, TypeScript ~6.0.3, `expo-secure-store` ~57.0.4.

**Spec:** `docs/superpowers/specs/2026-11-21-lab6-auth-design.md`

## Global Constraints

- Токен постоянно хранится только в `expo-secure-store` под ключом `campus_planner.access_token`; в `AsyncStorage`, параметрах маршрута, `.env`, исходниках и логах токена быть не должно.
- Пароли и реальные тестовые учётные данные не коммитятся и не логируются; в `.env` только публичный `EXPO_PUBLIC_API_URL`.
- `authorizedFetch` инициирует сброс сессии только при HTTP `401`; при `5xx`, `4xx` (кроме `401`) и сетевой ошибке сессия сохраняется.
- Пока `isLoading === true`, группы маршрутов не монтируются и перенаправления не происходит.
- Список задач остаётся локальным: `TasksContext`, экраны создания/редактирования/удаления/поиска/фильтрации/статистики не переводятся на сервер.
- Все экраны и функции ЛР1–ЛР5 должны остаться работоспособными; тексты интерфейса — на русском.
- Ключ `SecureStore` содержит только латиницу, цифры, `.`, `-`, `_` (символы `@` и `/` запрещены).
- После каждого этапа: `npx tsc --noEmit` и `npx expo lint` без ошибок.

## Review Focus

- Прямой переход на `/task/<id>` или `/edit/<id>` без сессии: должен открыться только экран входа, без кадра с защищённым экраном. Проверяется в Task 8.
- Сохранённый токен + сеть недоступна или `/auth/me` вернул `5xx`: токен остаётся в `SecureStore`, пользователь видит вход с пояснением, следующий запуск снова пытается восстановить сессию. Проверяется в Task 4 и Task 8.
- `/auth/me` вернул `401`: токен удаляется, пояснение не показывается. Проверяется в Task 4 и Task 8.
- Пустые/пробельные поля и двойное нажатие «Войти»: запрос не уходит при пустом логине/пароле, повторная отправка блокируется до завершения. Проверяется в Task 7 и вручную в Task 8.
- Неверный пароль (`401`) против сетевой ошибки: в первом случае показывается сообщение сервера, во втором — сообщение о подключении; кнопка снова активна. Проверяется в Task 7 и вручную в Task 8.
- Смена пользователя: задачи, созданные пользователем A, не видны пользователю B. Проверяется структурой Task 6 и вручную в Task 9.
- Выход: токен удалён, защищённые экраны недоступны по кнопке «Назад» и по прямой ссылке. Проверяется в Task 9.

- [ ] **Step 3: Создать `src/api/http.ts`**

`API_BASE_URL`: взять `process.env.EXPO_PUBLIC_API_URL`, обрезать пробелы и завершающие `/`; если переменная пустая — использовать `https://campus-api.mkseva.workers.dev`.

`ApiError`: сохраняет `status: number | null`; для сетевой ошибки `status = null`.

`readErrorMessage(response)`: попытаться прочитать JSON `{ error }`; если строки нет или тело не JSON — вернуть `Ошибка сервера (${response.status}).`

`authorizedFetch`:
- копирует заголовки из `init.headers` через `new Headers(...)`;
- всегда ставит `Authorization: Bearer <token>`;
- ставит `Content-Type: application/json`, только если передан `body` и заголовка ещё нет;
- вызывает `fetch(`${API_BASE_URL}${path}`, { ...init, headers })`;
- если `response.status === 401` и передан `onUnauthorized`, дожидается `await onUnauthorized()`;
- возвращает `Response` в любом случае; сетевые исключения не перехватывает и `onUnauthorized` при них не вызывает.

**Files:**

export function saveToken(token: string): Promise<void>;

(Типы `Context`, `ReactElement`, `ReactNode` импортируются из `react`.)

- [ ] **Step 1: Создать `authStorage.ts`**

Ключ `campus_planner.access_token`; обёртки над `SecureStore.setItemAsync`, `getItemAsync`, `deleteItemAsync`. Не логировать значение токена и не добавлять `@` или `/` в ключ.

- [ ] **Step 2: Создать `AuthContext.tsx`**

Состояние: `user`, `accessToken`, `isLoading = true`, `authNotice = null`. `isAuthenticated = Boolean(user && accessToken)`.

`clearSessionOn401` (стабильный `useCallback`): удалить токен через `removeToken()` (ошибку удаления проглотить, но состояние очистить), затем `setUser(null)`, `setAccessToken(null)`, `setAuthNotice(null)`.

Восстановление при монтировании:
```text
try token = await readToken() catch token = null
if token отсутствует -> isLoading = false, выход
try:
  user = await getCurrentUser(token, clearSessionOn401)
  setAccessToken(token); setUser(user)
catch error:
  if error instanceof ApiError && error.status === 401:
    await clearSessionOn401()
  else:
    authNotice = 'Не удалось проверить сохранённую сессию. Проверьте подключение и войдите снова.'
finally:
  isLoading = false
```
Токен при сетевой ошибке/`5xx` не удалять. Эффект должен игнорировать результат после размонтирования (флаг `cancelled`).

`signIn`: `const data = await apiSignIn(credentials)`; `await saveToken(data.accessToken)`; установить `accessToken` и `user`; `authNotice = null`. Ошибку пробросить в форму.

`signOut`: `await removeToken()` (при ошибке всё равно очистить состояние); `setAccessToken(null)`, `setUser(null)`, `setAuthNotice(null)`.

Значение контекста мемоизировать через `useMemo`; функции — через `useCallback`.
