Сейчас мешает не функциональность, а готовность к показу:

## 5. Рассмотренные подходы

### 5.1 Собственная функция

1. **Календарный список (выбран).** Группировка по срокам: «Просрочено», «Сегодня», «Завтра», «На этой неделе», «Позже», «Без срока», «Выполненные». Заметно на демо, использует существующие данные, даёт естественные пустые состояния по секциям.
2. **Сортировка по дедлайну.** Переключатель «По приоритету / По сроку» с сохранением в AsyncStorage. Малый риск, но функция тонкая и почти не отличается от текущей сортировки; пустого состояния нет.
3. **Приоритетные напоминания.** Баннер «Просрочено N, сегодня M» с переходом в отфильтрованный список. Заметно, но частично дублирует статистику.

### 5.2 Реализация списка

- **A. Плоский `Animated.FlatList` с секциями-строками (выбран).** Сохраняет текущие анимации, свайпы, `RefreshControl`, шапку, поиск и фильтр. Заголовки секций не липкие, но для демонстрации это не критично. Риск минимальный.
- **B. `Animated.SectionList`.** Нативные секции и липкие заголовки, но `itemLayoutAnimation` с SectionList работает ненадёжно; придётся заново проверять свайпы и анимации. Больше риска ради косметики.
- **C. Отдельный экран «Календарь».** Основной список не трогаем, но появляется дублирование данных и UI, функция выглядит приделанной сбоку, а на защите придётся объяснять два списка.

## 6. Календарный список

### 6.1 Секции и правила

| Секция | Условие | Сортировка |
| :-- | :-- | :-- |
| Просрочено | `dueDate` раньше сегодняшнего дня, статус `active` | по сроку, затем по приоритету |
| Сегодня | `dueDate` равен сегодня | по сроку, затем по приоритету |
| Завтра | `dueDate` равен завтра | по сроку, затем по приоритету |
| На этой неделе | от 2 до 7 дней вперёд включительно | по сроку, затем по приоритету |
| Позже | больше 7 дней вперёд | по сроку, затем по приоритету |
| Без срока | `dueDate: null` или невалидная дата | по приоритету |
| Выполненные | статус `completed`, только при фильтре «Все» | по приоритету |

Правила:

- при фильтре «Выполненные» показывается одна секция «Выполненные», без дат;
- при фильтре «Активные» секции «Выполненные» нет;
- при фильтре «Все» активные задачи идут по датам, выполненные — отдельной секцией в конце;
- выполненная задача с прошедшим сроком не попадает в «Просрочено»;
- пустые секции не показываются;
- поиск применяется до группировки, пустые секции после него исчезают;
- удаляемые задачи (`pendingIds`) исключаются до группировки;
- в заголовке секции показывается количество: «Сегодня · 2»;
- «На этой неделе» — это ближайшие 7 дней, а не календарная неделя; так поведение предсказуемо в любой день.

### 6.2 Типы и функции

Новый файл `src/utils/taskSections.ts`:

```ts
export type TaskSectionKey =
  | 'overdue'
  | 'today'
  | 'tomorrow'
  | 'thisWeek'
  | 'later'
  | 'noDueDate'
  | 'completed';

export interface TaskSection {
  key: TaskSectionKey;
  title: string;
  tasks: Task[];
}

export type TaskListRow =
  | {
      kind: 'section';
      key: string;
      title: string;
      count: number;
      overdue: boolean;
    }
  | { kind: 'task'; key: string; task: Task };

export function groupTasksByDueDate(
  tasks: Task[],
  filter: TaskStatusFilter,
): TaskSection[];

export function buildTaskRows(sections: TaskSection[]): TaskListRow[];
```

- `groupTasksByDueDate` опирается на `parseDateOnly` и `sortTasksByPriority` из `src/utils/task.ts`.
- Сравнение дней идёт по локальным датам, без UTC.
- `buildTaskRows` разворачивает секции в плоский массив строк для `FlatList`.
- Ключи строк: `section:overdue`, `task:<id>` — стабильные, без индексов.

### 6.3 UI списка

- Новый компонент `src/components/task/TaskSectionHeader.tsx`: заголовок, количество, акцент `danger` для «Просрочено».
- `app/(app)/index.tsx`:
  - данные: `tasks` → без `pendingIds` → локальный фильтр статуса → поиск → `groupTasksByDueDate` → `buildTaskRows`;
  - `data={rows}`, `keyExtractor={(row) => row.key}`;
  - `renderItem` различает `section` и `task`;
  - карточки задач по-прежнему оборачиваются в `Animated.View` с `SlideInRight`/`FadeOut`;
  - заголовки секций рендерятся отдельной строкой, без свайпа;
  - `ListHeaderComponent` со статистикой, поиском и фильтром не меняется;
  - `ListEmptyComponent` и тексты пустых состояний не меняются;
  - `RefreshControl`, баннер ошибки и плашка отмены не меняются.

### 6.4 Крайние случаи

- `dueDate: null` и невалидная дата → «Без срока».
- Полночь: секции пересчитываются при следующем рендере; отдельного таймера нет — осознанное упрощение.
- Смена фильтра: старые данные `keepPreviousData` проходят локальный фильтр, затем группировку.
- Оптимистичный toggle: задача сразу уходит в «Выполненные» при «Все» или исчезает при «Активные».
- Отмена удаления: задача возвращается в свою секцию.
- Подсветка создания: работает по `lastCreatedId` внутри любой секции.

### 7.2 `TaskQueryGate`

Новый `src/components/task/TaskQueryGate.tsx`:

```tsx
interface TaskQueryGateProps {
  id: string | undefined;
  query: UseQueryResult<Task, Error>;
  onBack: () => void;
  children: (task: Task) => ReactNode;
}
```

Поведение:

- `id` нет или ошибка `404` → «Задача не найдена» + «Назад к списку»;
- `isPending` → спиннер;
- `isError` или нет данных → «Не удалось загрузить задачу» + «Повторить»;
- иначе → `children(task)`.

Используется в `app/(app)/task/[id].tsx` и `app/(app)/edit/[id].tsx`; дублирующиеся импорты `ActivityIndicator`, `EmptyState`, `ApiError` и стили `centered` удаляются.

### 7.5 Ошибки без технического текста

- `getErrorMessage` перестаёт возвращать сырой `error.message` сервера и маппит статусы:
  - `null` → «Не удалось подключиться к серверу. Проверьте интернет и повторите попытку.»;
  - `400` → «Проверьте введённые данные.»;
  - `401` → «Сессия истекла. Войдите снова.»;
  - `403` → «Нет доступа к этой операции.»;
  - `404` → «Запись не найдена.»;
  - `429` → «Слишком много запросов. Попробуйте позже.»;
  - `5xx` → «Сервер временно недоступен. Попробуйте позже.»;
  - иначе → «Не удалось выполнить запрос. Попробуйте ещё раз.».
- Экран входа обрабатывает `401` как «Неверный логин или пароль.», `400` как «Проверьте логин и пароль.», остальное — через `getErrorMessage`.
- `ApiError.message` остаётся для отладки, но UI его не печатает.
- `readErrorMessage` продолжает разбирать тело ответа, но его текст не показывается пользователю.
